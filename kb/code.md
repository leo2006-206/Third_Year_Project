## Segment Cache replacement policy — IDEAS (2026-11-04, from the 2 docs/ PDFs + set-2 data; NOT agreed with user yet)
- Paper A (Dean/Ramdhany/Porter ACSOS-C 2025, render-cost caching OBM): hit ratio != total render cost; policies FIFO/LRU/LFU/S3-FIFO + RC-FIFO (insert at head if cost >= head's cost; starves others, -20% hit ratio) + cost-partitioned cache (bins per cost range, LRU in each bin, fixed sizes). Gains only when bin count/size tuned (+5% helps, +10% loses); future work = online partition tuning. Capacity 2% of trace bytes. Metric: total runtime (sum miss cost) + hit ratio.
- Paper B (Ma et al. IEEE Access 2018, WGDSF): GDSF H = L + Fr*Cost/Size, L = H of last evicted (aging). WGDSF H = L + SC*WDT*WTF: SC = Cost/log(Size); WTF = sum_i F_i/T_i (hits per interval / interval length = recency-weighted freq); WDT = share of docs of that type. Admission: if new doc j would be among the lowest-H victims -> do not cache j. Wins at small caches (1-20%), weak with short TTL and loop/continuous patterns.
- Our data (stat/run_*/mct_const_flat_none_1.csv): ~300 req/run, ~185 distinct paths, 36-40% repeats = 39-45% of work+asset saved by an infinite cache; 144/187 paths seen once (one-hit wonders); reuse distance median 32-58 req, p90 110-175; size median 2.2 MB (max 9.3), distinct total ~450 MB (fits om RAM -> capacity MUST be constrained, sweep e.g. 2/5/10/20% of distinct bytes, justify as scale-down); work p10/p50/p90 2.1/3.7/9.9 s; work per MB p10/p90 0.84/17 (20x); corr(work,size)=0.08, corr(work,count)=0.08 -> cost is independent info, cost-aware should matter.
- Ideas: (1) GDSF with Cost = machine-neutral predicted miss cost (lookup.csv/cost model, + asset ~1.75 s) instead of bins (no bin tuning = answers paper A's open problem). (2) Size term: S vs log S (paper B) -> compare. (3) Frequency: WTF or simpler decayed count (half-life ~ reuse distance). (4) WDT analogue = class prior (show, segment index; seg0 41-46% of requests) as initial Fr for cold items. (5) WGDSF admission (reject if lowest) +/- ghost list / 2nd-hit admission, cost-gated (one-hit wonders 77% of paths). (6) Baselines: FIFO, LRU, LFU, S3-FIFO, RC-FIFO, cost-bins LRU (paper A), GDSF(Cost=1). (7) Metrics: hit ratio, byte HR, cost-hit ratio (sum saved predicted cost / total), replay latency. (8) Python trace sim first on stat/run_* + seed2042 (like aco_sim), then Rust: CacheTable stays key->file, policy struct separate (trait on_hit/admit/victims). (9) Load-aware cost extension (miss in a burst costs queueing; queue 82-88% of latency) - later. (10) In-flight repeats -> coalescing (cache #3) interacts; measure share of repeats while first still in flight.
- USER DECISION 11-04: segment cache policy = SIMPLE (LRU or LFU), or rebuild paper A's cost-bin cache for segments. GDSF/WGDSF ideas above NOT wanted. Paper A gains are small/fragile (synthetic: -2 s, -14 s with +5% to the costly bin, gone at +10%; BBC trace: unified FIFO best 943 s, 3P/13P mostly worse, only LRU/RC-FIFO -1-2 s with velocity bins).
